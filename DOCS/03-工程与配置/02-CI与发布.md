# 02 · CI 与发布

> 文件：`.github/workflows/{ci,release}.yml`、`.github/ISSUE_TEMPLATE/bug_report.yml`、`.gitattributes`

## 1. CI（ci.yml）—— 合并门禁

**触发**：push 到 main / 任意 PR。

| Job | 运行环境 | 步骤 | 意义 |
| --- | --- | --- | --- |
| `frontend` | windows-latest | checkout → setup-node 20（cache npm）→ `npm ci` → `npx vue-tsc -p tsconfig.app.json --noEmit` → `vite build` | 类型检查 + 构建产物验证 |
| `backend` | windows-latest | setup-rust（稳定版）→ 缓存 cargo/target → `cargo check` → `cargo test` | Rust 编译 + 全部单测 |

要点：
- 前端**无单测**（未配置 vitest/jest），质量门槛 = vue-tsc 严格类型检查 + 构建成功；
- 后端 `cargo test` 是唯一自动化测试关卡（模块内 `#[cfg(test)]`）；
- Node 20 + 锁文件缓存（`package-lock.json` hash）加速。

## 2. 发布（release.yml）

**触发**：手动 `workflow_dispatch` / 推送 `v*` tag。

| Job | 说明 |
| --- | --- |
| `build-release` | windows-latest：checkout → node 20 → rust stable → 缓存 → `npm ci` → `npm run build` → `npm run tauri build` → 上传 `src-tauri/target/release/bundle/**/*` artifacts → 创建 GitHub Release（draft:false, prerelease:false, generate_release_notes:true） |

要点：
- 发布产物仅 Windows（NSIS 安装包等）；Linux 目标（deb/appimage）在 CI 未构建（本地可 `tauri build`）；
- tag 命名约定 `v{version}`（update_cmds 的 `check_update` 解析 GitHub Releases 的 `tag_name`——**发布必须打 `v` 前缀 tag**，否则检查更新失效）；
- 版本号三处一致：Cargo.toml / package.json / tauri.conf.json（打 tag 前核对）。

## 3. Issue 模板

- `bug_report.yml`：结构化 bug 报告（版本 / 平台 / 复现步骤 / 预期与实际 / 日志附件）——便于收集诊断信息。

## 4. .gitattributes

- 行尾/文本规范化（CRLF ↔ LF 策略，Windows 项目必备）：二进制（png/ico/icns）标记 binary，文本统一 LF 提交。

## 5. 发布检查清单（手动发布流程）

1. 版本号三处一致（Cargo.toml / package.json / tauri.conf.json）；
2. `cargo test` + `vue-tsc` 全绿（CI 会兜底）；
3. 推送 `v0.1.x` tag → release.yml 自动构建发布；
4. 发布说明：功能变更 + 验证方式（遵循仓库提交/发布信息约定，不写内部流程）；
5. 内置 FFmpeg 不打包进安装包（首次运行向导下载/系统安装）——发布说明需提示用户。

## 6. 已知陷阱

- **CI 仅 Windows**：Linux 编译问题不会被 CI 捕获（本地 Linux 开发者需自行 `cargo check`）；跨平台改动（cfg 分支）要人工验证。
- release workflow 的 `GITHUB_TOKEN` 权限：创建 Release 需要 `contents: write`（默认 workflows 权限需在仓库设置确认）。
- `.github/ISSUE_TEMPLATE` 与 GitHub 表单 schema 绑定：改模板结构需匹配 GitHub 官方 schema，否则表单不渲染。
- 前端构建顺序（`beforeBuildCommand: npm run build`）：Tauri 构建前自动编译 dist——本地改前端代码后直接 `npm run tauri build` 即可，无需手动先 build。
