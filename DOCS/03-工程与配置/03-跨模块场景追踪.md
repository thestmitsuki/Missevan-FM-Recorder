# 03 · 跨模块场景时序图（补充深度追踪）

> 本文用时序图补充「数据流与核心场景」的模块级细节，便于跨文件追踪。路径省略前缀。

## 场景 A：开播 → 自动录制 → 结束（完整时序）

```
DetectionLoop (detector/loop.rs)
  │  每轮: sleep(interval + 抖动) → mock? → 逐主播 check_live
  │
  ├─► spider.rs::MissevanClient::check_live(room_id)
  │     │  网络插桩 → logging/network.rs（全局单例）
  │     └─► LiveCheckResult{is_live, stream_url, ...} | CheckErrorKind
  │
  ├─► live_cache[room_id] = is_live
  ├─► update_anchor（配置落盘直播状态）
  ├─► build_statuses → emit "recording_status_changed"（归并 merge_live_state）
  │
  └─ is_live && enable_check && !is_recording ?
       ├─ disk.rs::check_disk_space（阈值, 0=不限制）→ Low → 通知 DISK_LOW（DiskNotifyThrottle 节流）
       ├─ spider::get_stream_url → Err → 通知 REC_API_FAILED
       ├─ register_pending_start(anchor_id, cancel)   // 延迟窗口可取消
       ├─ sleep(pre_record_delay_secs)
       ├─ 复检：仍直播 && 未在录？
       └─ engine.rs::start_ffmpeg_recording
             ├─ is_recording(anchor_id) → RC_ALREADY_RECORDING（双录防御 #1）
             ├─ 并发上限检查 → RC_CONCURRENCY_LIMIT
             ├─ builder.rs::FfmpegCommandBuilder（-vn/-b:a/-f segment/-rw_timeout/UA/代理/cookie）
             ├─ template.rs::render_filename_template（路径消毒, 防逃逸）
             ├─ deduplicate_output_path（已存在 → _2/_3）
             ├─ spawn ffmpeg（CREATE_NO_WINDOW）→ insert_process
             ├─ AppState.tasks.insert(Task{cancel_token, handle, output_path, pid})
             ├─ emit recording_status_changed（录制中）
             ├─ notifier: REC_START
             └─ monitor.rs::monitor_recording（新任务）
                   ├─ 每5s: 子进程存活? + 磁盘检查（节流）
                   ├─ cancel_token 触发 → 优雅终止
                   └─ 退出 → cleanup_on_recording_end
                         ├─ cleanup.rs::run_cleanup（按天/总量, 跳过活跃）
                         ├─ file_cache.rs::refresh（emit recording_files_changed）
                         ├─ AppState.push_history（≤50）
                         ├─ notifier: REC_END / REC_ERROR / REC_CRASH
                         └─ 重试?（可重试原因 && max_retries → 延迟后重走防线）
                               └─ post_record_action（none/open_folder/command）
```

## 场景 B：手动停止

```
前端「停止录制」→ api.ts stop_recording → recording_cmds.rs
  ├─ cancel_pending_start（延迟窗口）
  ├─ tasks: cancel_token.cancel() + await JoinHandle ≤5s
  └─ 兜底：FfmpegRecorder.processes 按 anchor 终止残留进程
      → monitor 退出 → 场景 A 的结束出口
```

## 场景 C：配置保存链

```
设置页表单 → configStore.saveConfig → api.ts save_config → config_cmds.rs
  ├─ ConfigManager::save（校验 → std Mutex 原子写 tmp+rename → 备份轮转 ≤5）
  ├─ output_dir 变化 → file_cache 重建（fs_walk 安全遍历）
  ├─ autostart 变化 → 系统自启写入
  ├─ log_level 变化 → LogLevelReload 热更新
  └─ 前端 Toast「已保存」+ dirty 复位
```

## 场景 D：首启向导

```
启动（无 config.toml）→ lib.rs setup
  ├─ wizard.show() + main.hide()
  └─ 前端 WizardView（wizard 窗, 仅向导权限）
        ├─ 步骤2: wizardStore.staged 暂存（不写盘）
        ├─ 步骤3: run_wizard_health_check（checker 候选与引擎一致）
        │         └─ Windows: download_ffmpeg（流式, download:progress, 解压到 {exe_dir}/ffmpeg/）
        └─ 步骤4 完成 → finish_wizard
              ├─ wizard.destroy() → main.show()/focus()
              ├─ file_cache 初始扫描
              └─ detection_wake.notify_one() → 立即检测
    配置落盘: stagedToConfig.ts → save_config（含 ffmpeg_path）
```

## 场景 E：通知链路

```
任意业务点 → NotificationDispatcher::notify(code, level, title, msg)
  ├─ from_settings(&GlobalConfig) → NotifySettings 过滤矩阵
  ├─ should_send_system → windows_toast（AUMID 注册, 非 PowerShell）
  ├─ should_send_sound → 系统提示音
  ├─ emit "app:notification" → 前端 notificationStore（≤50 条）
  └─ RingBuffer（500 条）→ get_notifications（通知中心）
```

## 场景 F：退出

```
窗口 close → on_window_event
  ├─ should_hide_to_tray(close_behavior, is_exiting, tray_available)?
  │     ├─ true → prevent_default + hide（后台运行）
  │     └─ false → do_shutdown
  └─ 托盘「退出应用」→ do_shutdown
        ├─ ConfigManager 保存
        ├─ DetectionLoop 停止（running=false）
        ├─ cancel 全部 tasks（等 ≤5s）
        ├─ try_state FfmpegRecorder → 强制终止残留进程
        └─ app.exit(0)
```

## 场景 G：双录防御三层（按序触发）

| 层 | 位置 | 机制 | 防什么 |
| --- | --- | --- | --- |
| 1 | 单实例锁（启动期） | fs2 独占文件锁 | 应用双开 |
| 2 | engine `is_recording` | FfmpegRecorder 进程表锁内去重 | 同主播重复启动 |
| 3 | 并发上限 | AppState.active_count ≥ max | 资源超载 |

三层缺一不可：锁防双开，进程表防同实例内重复，上限防超载。**改动任一层的逻辑必须回归其他两层**（如新增长延迟重试路径绕过进程表 = 回归双录防御）。

## 场景 H：文件安全红线（S1）

```
任何遍历输出目录的路径：
  fs_walk::collect_files（symlink_metadata 不跟随链接）
    ├─ file_cache::scan_output_dir（文件列表/树）
    ├─ cleanup::scan_recording_files（清理候选）
    └─ 禁止新增「手写递归遍历」（历史 S1 数据丢失修复）
删除/重命名前：
  ensure_within_output_dir（防前缀欺骗 out2 ⊄ out）
```
