# 04 · 开发指南

## 1. 环境要求

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 20（CI 用 20） | 前端构建 |
| npm | 随 Node | `package-lock.json` 锁定 |
| Rust 工具链 | ≥ 1.89.0（MSRV，实测 1.96 通过） | 依赖树最高 rust-version = notify-rust 4.18.0 的 1.89.0 |
| Tauri CLI | 2.x（devDependencies 自带 `@tauri-apps/cli`） | `npm run tauri` |
| Windows SDK / WebView2 | Windows 构建需要 | Tauri 2 标准要求 |
| FFmpeg | 运行期可选 | 便携版 `{exe_dir}/ffmpeg/` 或 PATH；Windows 向导可自动下载 |

## 2. 常用命令

```bash
# 前端
npm install            # 安装依赖
npm run dev            # 仅前端 dev server（http://localhost:1420）
npm run build          # vue-tsc 类型检查 + vite 构建（产出 dist/）
npm run preview        # 预览构建产物

# Tauri
npm run tauri dev      # 前端 dev + 后端 debug 一体化开发
npm run tauri build    # 生产构建（bundle NSIS / deb / appimage）

# 后端（在 src-tauri/ 下）
cargo check            # 类型检查
cargo test             # 全部单测（模块内 #[cfg(test)]）
cargo test <模块名>    # 只跑某模块测试
cargo clippy           # lint（建议）
cargo fmt              # rustfmt（提交前必跑）
```

> 注意：`npm run tauri dev` 会同时启动 vite；纯前端调试时 Tauri 相关 API（invoke/listen）在浏览器不可用，`services/window.ts` 等已做 try/catch 兜底，但业务命令无法在浏览器验证。

## 3. 项目结构约定（新增代码时的落点）

### 后端（`src-tauri/src/`）

| 你要做的事 | 落点 |
| --- | --- |
| 新增一个前端可调用的功能 | `api/` 新建或扩展命令模块 → `lib.rs` 的 `generate_handler!` 注册 → `permissions/*.toml` 定义 → `capabilities/*.json` 授权 |
| 新增业务规则 / 领域算法 | `domain/`（config / detector / recorder / services / spider / tools） |
| 新增平台能力（托盘 / 通知 / 锁 / 日志 / 检查） | `infrastructure/` |
| 新增可序列化错误 | `infrastructure/error/types.rs`（错误码常量 + AppError 构造器） |

### 前端（`src/`）

| 你要做的事 | 落点 |
| --- | --- |
| 新页面 | `views/<name>/` + `router/index.ts` 路由 + `locales/*` 文案 |
| 新状态 | `stores/`（Pinia setup 风格）；UI 偏好走 localStorage，业务数据走后端 |
| 新 Tauri 调用 | `services/api.ts` 集中封装（禁止页面内直接 invoke） |
| 新事件 | `services/events.ts` 注册 + `onXxx` fan-out + store 订阅 |
| 可复用 UI | `components/ui/`（shadcn 风格：reka-ui 原语 + cva 变体）；业务组件 `components/common/` |
| 类型契约 | `types/`（与后端 DTO 逐字段对齐，注释标明来源文件） |

## 4. 编码约定（仓库既有规范，务必遵守）

1. **前端**：TypeScript strict；`vue-tsc -b` 必须通过；所有 key snake_case；`import type` 用于纯类型；路径别名 `@/`。
2. **后端**：rustfmt 默认格式；`api / domain / infrastructure` 分层；模块头部 `//!` 文档注释写明设计动机与坑；重要决策用注释标注审查编号（如 `S2a`、`M1`、`B2`、`L5`——历史审查追踪体系，新增修复请沿用该风格标注）。
3. **错误处理**：一律返回 `AppError`（带错误码），命令层不 panic；`Result<_, AppError>` 全链传播。
4. **安全红线**（历史安全审查结论，禁止回归）：
   - 文件遍历/清理**不得跟随**符号链接与 junction（`fs_walk.rs`，S1 数据丢失修复）；
   - 清理/删除前校验路径在输出目录内（`ensure_within_output_dir`，防前缀欺骗）；
   - 敏感字段（Cookie / 代理密码）落盘必须混淆（`crypto/mod.rs` `enc:v1:`），日志必须脱敏（`sanitize_message`）；
   - 打开浏览器仅放行 http/https（`is_browsable_url`）；
   - 录制启动必须过 `is_recording + 并发上限` 双检查（双录防御）。
5. **注释语言**：中文注释为主（项目既有风格），关键算法/坑点必须写「为什么」。
6. **提交信息**：描述产品变更 + 理由 + 验证方式；不提及内部流程/工具名。

## 5. 测试策略

- **后端**：模块内 `#[cfg(test)]` 单测为主（config 解析/校验、模板渲染、路径清理、退避算法、通知过滤矩阵、错误码、mock store、单实例锁、环形缓冲、日志脱敏等，覆盖率高）。新增领域逻辑**必须**带单测（仓库惯例）。
- **前端**：无单测框架（未配置 vitest/jest）；质量靠 `vue-tsc` 类型检查 + 人工验证。CI 只跑类型检查与构建。
- **CI**（`.github/workflows/ci.yml`）：frontend job（windows-latest，npm ci → vue-tsc --noEmit → vite build）；backend job（windows-latest，cargo check + cargo test）。
- **发布**（`.github/workflows/release.yml`）：推 `v*` tag 或手动触发 → Windows 构建 → 上传 release artifacts（NSIS 等）。

## 6. 本地运行排障速查

| 现象 | 原因/解法 |
| --- | --- |
| `cargo check` 报 MSRV 错误 | 工具链 < 1.89.0，升级 rustc |
| 前端 invoke 失败 `command xxx not found` | 命令未注册 `generate_handler!` 或权限未在 capabilities 授权 |
| 向导窗关闭后主窗不显示 | `finish_wizard` 依赖 wizard 窗销毁 + main 显示/聚焦；检查窗口 label |
| 双开应用未拦截 | `single_instance.rs` 锁文件路径：Windows `%LOCALAPPDATA%...\cache\missevan-recorder` |
| FFmpeg 找不到 | 候选顺序：配置路径 → `{exe_dir}/ffmpeg/ffmpeg.exe` → PATH；Linux 用系统包 |
| 录制不启动 | 检查 enable_check / 并发上限 / 磁盘阈值 / 流地址获取失败（看日志与通知） |
| 调试页空白 | 需先在「设置 → 关于」开启调试模式 |
